## TRIẾT LÝ CỦA KẾ HOẠCH NÀY

Muốn Tuần 2–3 code **không phụ thuộc lẫn nhau**, điều kiện bắt buộc là: **hết Tuần 1, mọi ranh giới giữa các module phải được "đóng băng" thành hợp đồng (contract)** — gồm:

1. **TypeScript interfaces** dùng chung (`Strategy`, `StrategyGenerator`, `NewsProvider`, event payloads...)
2. **Database schema** (Prisma schema) đầy đủ
3. **REST API spec** (endpoint, request/response shape)
4. **WebSocket Event Catalog** (tên event + payload)
5. **Sample/seed data** (candle mẫu, news mẫu) để mỗi người tự test module của mình mà không cần chờ người khác

Khi có 5 thứ trên, mỗi người có thể code, unit test, và **giả lập (mock) phần còn lại của hệ thống**. Tuần 3 mới là lúc "cắm" các module thật vào nhau (integration) — lúc đó phụ thuộc gần như không còn là rủi ro vì contract đã cố định từ đầu.

⚠️ Quy tắc quan trọng: **Sau ngày 7, không ai được tự ý đổi interface/schema/event một mình.** Nếu cần đổi, phải báo cả nhóm — nếu không, các module sẽ vỡ khi tích hợp ở Tuần 3.

**Nguyên tắc chính: ai làm backend phần nào thì tự làm frontend phần đó.** Mỗi người sở hữu trọn 1 nhóm module theo chiều dọc, bao gồm cả phần backend lẫn frontend liên quan — code đúng theo contract đã chốt ở Tuần 1, và với bất kỳ dữ liệu đến từ module khác thì dùng seed data / fixture / mock thay vì chờ người kia code xong. ## VÌ SAO CÁCH CHIA NÀY GIÚP TUẦN 2-3 THỰC SỰ ĐỘC LẬP

- Mỗi người sở hữu **trọn vẹn 1 nhóm module theo chiều dọc** (không ai code chung 1 file/1 class với người khác) → không đụng code.
- Điểm chạm duy nhất giữa 4 người là **interface/schema/event đã chốt ở Tuần 1** — đây là thứ ổn định, không đổi trong Tuần 2.
- Dùng **fixture/mock** thay cho module thật của đồng đội khi test → không ai phải _chờ_ người khác code xong mới bắt đầu.
- Tuần 3 chỉ còn việc "cắm dây" (integration) chứ không phải chờ nhau code — rủi ro chậm tiến độ giảm mạnh.
